# 制作フローの変更記録

日付：2026-09-24

## 方針と変更理由

最初の統合ではmainの詳細設定・真実丸を通常の制作画面に残し、kawata-workの攻撃・舞台入力は互換APIとしてのみ保持していた。今回の利用者指示により、**制作UIの外観はmain、入力と生成フローはkawata-work**へ変更する。

## 現在の操作

1. mainのコード描画によるタイトルで「Game Start!」。
2. モード選択で「ゲーム作成」。
3. 攻撃手法を1～3件と、事件の舞台を選択。
4. 「Scenario案を作成」。
5. 独立レビュー済みのPreviewで事件・攻撃・自動構成したNetworkを確認。
6. 承認後、証拠・ゲームの生成と評価を実行し、完成したゲームを自動保存。

タイトル・モード選択・保存一覧・削除・設定・遊び方・終了・完成画面からの復帰はmainの部品を維持した。作成方法の選択と詳細なNetwork・日時・難易度の入力画面は通常のフローから外した。上部の進行表示は「攻撃と舞台 → Scenario Preview → Game Generation」に合わせた。

## 攻撃の選択規則

- kawata-workの8選択肢と5舞台を使用する。攻撃の順序付き入力は `scenario-selection` v1.0。
- 1件目は単独で成立する登録済みの候補から選べる。
- 2・3件目は `attackSelectionPaths` の選択済み列と一致する候補だけを表示する。1件目との関係だけではなく、直前の攻撃からの直接のENABLES関係が必要。
- 「追加しない」で1件・2件の構成も作れる。後続候補がない場合は後続の欄を表示しない。
- 前段を変更するとそれ以降を解除し、画面で通知する。同じ値の再選択では解除しない。
- 候補外の値や未知の舞台は送信しない。サーバーでもSchemaと技術グラフを再検証するため、UIの候補リストの偽造では制約を回避できない。
- Network、日時、難易度、調査方法は既存のkawata-workの規則で自動構成する。選択済みの完全なmanual Configurationを書き換える処理は追加していない。

## 実装

- `public/author.html`：mainのタイトル・メニューを保持し、制作フォームを攻撃連鎖3段と舞台に変更。
- `public/author.js`：kawata-workの候補絞込み・初期データ検査・選択保持を採用し、mainの保存・設定・終了操作と接続。`/api/author/selection` へ攻撃と舞台だけを送信する。応答待ちの二重送信・生成中の変更・無承認の生成を防ぐ。
- `public/style.css`：既存の配色・見出し・枠・ボタンを使用。幅のある画面は2列、小さい画面は1列に配置し、全体のスクロールを抑え、必要な場合だけ内容欄をスクロールする。
- `server/auto-generation-service.js`：通常の攻撃・舞台入口はBackendの確定基盤を独立Reviewへ渡し、不合格時に限定Revisionを実行するkawata-work方式へ変更。検証と承認のゲートは維持する。manual・真実丸APIは互換性のため以前の初回設計を維持する。
- `tests/helpers/author-dom.js`：送信待ち・失敗・Previewの模擬応答を追加。SVGの自己終了タグを正しく処理し、タイトル以外の画面をタイトル内部に誤って含めるテスト用DOMの問題も修正。

## 修正前の保存

`docs/history/author-creation-before-2026-09-24.js` に、変更直前のauthor.js・author.html・制作UIテストの全文をコメントとして保存した。日付と目的を記載し、動作中の画面には旧コードを読み込ませない。その他の変更箇所でも旧コードのコメントと日付を保持する。

# 攻撃別の生成確認

> 2026-09-24：以下の実AI結果はkawata-workでの過去の記録です。今回の統合はMockCodexRunnerによる検証を行い、実AI生成は再実行していません。17通りは通常画面が使用するselection APIの範囲です。16攻撃・1～6件のmanual APIは互換用に残しています。

## ClickFixで生成が停止した原因

提示された診断をコードと照合し、次を修正した。元の失敗セッションのJSONは受領していないため、その出力そのものを再実行した検証ではない。

1. 初期の2段階がともに「案内表示と端末実行の違い」を問う設計になっていた。第2段階は案内の要求IDと端末のプロセスID、親子関係、実行ユーザー、起動結果を比較する別の争点に変更した。被告人本人への帰属の裏付け不足も同じ最終争点内で扱う。
2. 当時は用語説明の全文がScenarioのRequirementへ渡らず、審査で前提知識が不足した。現在は問題作成用の攻撃・資料の背景情報をRequirementとEvidence生成へ渡し、必要な定義を問題文へ含める。事前の助手による案内は表示しない。
3. TESTIMONYでも参照する各Requirementのgroundへ追跡する必要がある。人物参照やstatementのgroundTruthRefsだけでは足りない。生成指示を明示し、差し戻しに対象の証拠ID・Requirement ID・許可されたgroundを含めた。
4. 証拠Importに失敗すると4択検査へ進まず、2回目に別の不備が初めて分かる構造だった。Schema適合済みdraftの参照と4択を同じ回で検査し、一緒に差し戻す。Importの不合格は維持し、後続工程を許可しない。
5. 4択の具体性検査は、対象の問題IDと引用中の実値の例を返す。整形JSON・配列・入れ子からも値を取り出し、request_id等の欄名を具体的な値として数えない。原文・正解・観測値をBackendで書き換えて検査を通す処理は行わない。

不正ログインと不正ファイルアップロードも、後半の争点を前半の言い換えにしないよう比較対象を具体化した。最終争点には被告人本人への具体的な主張と限定的反駁を組み込み、別の法廷は増やさない。取得元、攻撃、ネットワーク、最大修正回数、独立審査、証拠検証、最終評価は維持する。

実生成で追加確認した不整合：不正ログインの初回案内が未取得のセッション資料を「取得済み」と呼んでいたため、今回の資料を読む案内へ修正した。比較先は実際に取得済みの同じ攻撃の資料だけを列挙する。ランサムウェアの初回はプロセス記録から「権限」が分かるという期待推論になっていたため、定義済みの端末ID・実行ユーザー識別子・起動結果へ限定した。権限欄は追加していない。

## SQLインジェクションの不足条件

実AIの独立審査は、3回の検証で観測不足を指摘し生成を停止した。現在の`web_access_record`は必要な時刻・対象情報、`database_statement_record`は対象SQLを識別できる記録内容と保持条件を定義している。一方で教材は「Web入力がSQLの条件・構造へどう影響したか」を比較することを必須としている。入力本文、構造を読めるSQL本文・抜粋、要求とSQLの対応情報を観測できる条件が明記されていない。

SQL構造改変が攻撃の効果として成立することは、その内容がログから読めることの代用にならない。自動設定のevidenceAnswerに比較目標を書いても、観測条件を確認したことにはならない。技術入力にないログ本文・対応キー・観測結果を補わず、目標を一般的な人物帰属の限界だけへ縮小して合格にもしない。現在の入力範囲ではSQLインジェクションの教材完成は確認できない。

生成可能にするには、要求入力の記録範囲、実行SQLの記録範囲、両者を照合できる非秘密の対象情報と、その取得・保持条件を入力側で明示する必要がある。今回これらを推測で追加していない。

## 再現方法と範囲

既存の登録済み選択肢は単体8、2攻撃6、3攻撃3の計17通り。`scripts/verify-attack-generation.js`は各テスト用制作セッションを通常のPipelineに渡し、独立審査済みプレビューをテスト内で承認する。READYになったゲームを実際の進行ロジックでACQUITTEDまで操作する。ゲームの外部公開はしない。

```bash
# 通信を使わない17通りの模擬生成
node scripts/verify-attack-generation.js --output /tmp/mwscup-mock-report.json

# ClickFix単体の実AI生成
node scripts/verify-attack-generation.js --real --attacks clickfix --output /tmp/mwscup-clickfix-report.json

# 全17通りを実AI生成（同時実行は最大2）
node scripts/verify-attack-generation.js --real --concurrency 2 --output /tmp/mwscup-real-report.json
```

舞台は既定で企業。`--setting school`等で変更できる。複数攻撃は`--attacks phishing,clickfix,ransomware`のように発生順で指定する。結果にはREADY・ACQUITTED・各ゲートの状態・試行履歴・診断を残し、全件処理後に一件でも不合格なら終了コード1とする。`complete`は全件の処理完了であり、全件成功ではない。途中で中断したレポートは`complete: false`のままとなる。

実AI生成はCodex CLIのトークンを消費する。消費量を抑える場合は`--attacks`で対象を絞り、既定の逐次実行を使う。

`--capture-dir`は失敗解析用の任意オプション。非公開の合成解答を含むため、指定したローカルフォルダは0700、各ファイルは0600で作成し、Web配信ディレクトリや配布物へ置かない。通常の結果レポートには証拠・解答を含めない。Codex認証情報は読み出し・保存しない。

構造検証は17通り×5舞台で実施する。実AIの生成確認は各記載条件での実測であり、確率的な文章生成の全試行での成功保証ではない。未解消の不整合を残した成果物は引き続き公開しない。

## 途中までの実測結果（2026-09-22）

- 模擬生成：企業の全17通りでREADY・ACQUITTEDへ到達した。実AIによる内容審査の成功を示すものではない。
- 実AI生成：企業の単体8種類の処理が完了し、フィッシング、Stored XSS、不正ログイン、ClickFix、パスワードスプレー、ランサムウェア、不正ファイルアップロードの7種類でREADY・ACQUITTEDへ到達した。ClickFixは別の単体実行でも完了した。
- SQLインジェクションは上記の観測条件不足によりFAILEDとなった。推測による証拠追加やゲートの緩和は行っていない。
- 複数攻撃9通りの実AI検証は途中で停止しており、完了を確認できていない。

利用者の依頼により実行中の検証を停止し、追加テストは実行していない。実AIの一括検証開始後に加えた取得順の説明、ランサムウェアの期待推論、終了時の修正案内などを含む最終状態は、全体を再検証していない。最新コードの確認は利用者が上記コマンドで実施する。

# インシデントクラフト：調査と法廷の脚本

既存作品の人物・台詞・固有演出を複製せず、証言と資料の食い違いを発見する独自の法廷劇とする。技術的事実・人物設定は検証済みScenarioから変更しない。以下の固定台詞は`server/generation/dialogue-template.js`で管理し、ゲームの会話パネルへ順に表示する。角括弧の内容は公開済み資料・選択・成功後の解説から入れる。

事件ファイル画面には「事件のあらまし」を表示せず、弁護人の導入と報告書へのボタンを置く。

## 冒頭：事件報告書

ページ送りを挟まず、1ページに「何が起きた？」「疑われた理由」「最初に提出された資料」「証言者はこう話している」「あなたの仕事」を載せる。概要は日付・組織・対象システムと、検証済みの攻撃間のつながりを文章で説明する。人物、解答、未取得の記録は明かさない。疑われた経緯は「確認事項」「証言」「検察側の主張と疑いの経緯」に分けた短い事件説明とする。資料が提出されたこと、資料の読み取りに関する供述、そこから操作を被告人へ帰属させる検察側の立場を区別する。ログの本文・値・資料名・証言の直接引用はこの説明へ入れず、各資料・供述は別の欄に保持する。記録されていない人物対応は追加しない。被告人と操作の対応は未立証の主張として区別する。長い場合は縦スクロールで読む。

審理の案内：「疑いだけでは判断できません。弁護人は記録を調べ、主張の根拠を確かめてください。」

操作：「報告書を読んで調査へ」

## 調査：一つの場所、一つの手がかり

弁護士（あなた）：「記録はある。けれど、そこから何が言える？ 一つずつ確かめよう。」

弁護士（あなた）：「次は『[今回の調査先]』の資料を確認する。」

助手の立ち絵は調査机に表示するが、調査前の説明や読み取り手順の台詞は表示しない。攻撃の平易な定義と必要な用語は、その争点の4択の問題文に置く。例えばClickFixの最初の問題は保存された修復案内の記録値を扱い、次の問題では端末プロセスの記録を取得済み案内と比較する。一般知識を事件の観測事実や正解として扱わず、未知の実行結果・人物・後続被害を補わない。

操作：「調査を始める」→証拠と4択をまとめて表示。対象や方法を選ぶ欄と登録ボタンは置かない。現在の調査先の資料を既存の取得条件に従って自動取得し、複数ある場合は証拠一覧から切り替え、選択中の1件だけを表示する。過去の証拠も同じ一覧から選べる。後続の対象を先に開いたり、取得条件を省略したりしない。

選択中の証拠の下に、その回で検討する証言・4択を配置する。証拠を切り替えても4択の内容と推理の選択は変えず、切り替えだけでは採点・回数消費をしない。

表示：「証拠を読んで、推理する」。具体的な問いは生成された問題文に示す。

Evidence Agentは、現在の対象と過去の資料だけで答えられる問題を作る。例えば保存メールで表示URLとhrefを照合する問いは、メール単体で確認できる相違を扱う。後で調べるWebアクセスの結果まで推測させない。後に同じ攻撃の別資料を取得した段階では、取得済みの資料を再度照合し、攻撃固有の特徴と証明限界を解決後に説明する。選択だけでは採点しない。

操作：「この推理で法廷へ」。選んだ推理をサーバーに保存する。

## 法廷：証言、推理、証拠

検察官：「調査は終わりましたか。こちらの主張を確認しましょう。」

検察官：「[元の証言者の表示名]は、こう述べています。『[検証済みの証言本文]』」

弁護士（あなた）：「[調査でプレイヤーが選んだ推理]」

引用した証言と「あなたの推理・まだ確認前」は、キャラのセリフ枠とは分けた資料パネルに表示する。元の証言者と引用者を残し、誤った選択もそのまま未判定の仮説として表示する。

検察官：「推理だけでは足りません。裏付ける証拠を示してください。」

弁護士（あなた）：「この記録から、確かめていただきたい点があります。」

法廷の掛け合いは検察官1人と主人公の弁護士1人が担い、発言中の人物だけを立ち絵で映す。検察官は証言の引用者であり、元の証言者や技術的評価は変更しない。主人公は記録を丁寧に確かめる口調、検察官は主張を端的に示して根拠を求める口調とする。新しい人物設定は加えない。判決は人物の立ち絵なしの結果表示とする。

操作：「証拠を選ぶ」→登録済み資料の原文を確認→「この証拠を提示する」。提示時に初めて、保存済みの推理・証言・選んだ証拠・必要資料の取得をサーバーで判定する。推理を変える場合は調査へ戻る。

法廷は画面の高さに収め、人物・会話・推理を左、証拠選択と原文を右、提示操作を下部へ配置する。狭い画面では人物を小さくし、上下に配置する。長い原文や推理は欠落なくページに分け、資料一覧は4件ずつ（狭い画面は2件ずつ）切り替える。ページを切り替えても選択や残り提示回数を変更しない。

## 提示成功：次の調査先へ

「前の争点で確認できたこと」として、今回の根拠を説明する。未解決の答えは明かさない。

検察官：「その点は認めます。ですが、次の記録も説明できますか。」

弁護士（あなた）：「一つ、主張の穴が見えた。次の記録も確かめよう。」

弁護士（あなた）：「次は『[次の調査先]』の資料を確認する。」

この時点で初めて次の対象を開く。必要な調査対象の数だけ繰り返す。

## 提示失敗：同じ場所を再調査

検察官：「その推理は、この証拠では支えられません。同じ調査先に戻って、記録を読み直してください。」

弁護士（あなた）：「結論を急いだ。記録のどこまでが根拠になるのか、もう一度見よう。」

同じ調査対象へ直接戻り、取得済みの資料を保ったまま4択を選び直す。正解を示す個別ヒントは返さない。既存の各対象3回の提示上限を維持し、上限では審理終了とする。

## 最後の提示成功：判決

最後の提示が成功したら、最後の争点で確認できたことを示し、検察官と弁護士の会話を経て判決へ進む。

検察官：「……この記録だけでは、被告人が操作したとは言い切れません。有罪の主張は維持できません。無罪との判断を受け入れます。」

弁護士（あなた）：「記録が示すことを、最後まで確かめた。あとは、判決を待とう。」

操作：「判決を確認する」。会話送りは表示操作だけであり、再採点・提示回数の消費はしない。判決は裁判官の話者名に続け、最終判決と事件全体の説明を一つの枠に全文表示する。判決本文にはページ送りを置かず、争点一覧を省いて文章の領域を確保する。最後の争点の解説は折りたたみ式の「資料・結果」内に残すが、判決本文に重複して連結しない。

自動生成での判決：「被告人を無罪とします。」

説明は選択された攻撃ごとに経緯・成立原因・調査で比較した資料・分かる範囲を文章で示す。攻撃間の因果は検証済みGraphのENABLESがある場合だけ説明する。末尾に被告人への帰属の裏付けが足りないという判決理由を記す。事件設定として成立した経緯と、公開資料だけで証明できる範囲は区別する。

人物を断定する主張が支えられないという、検証済みの論証に基づく結末。記録にないアリバイ・真犯人・被告人の積極的な非関与は付け加えない。

## 資料と終了後の操作

資料は、保存メールの閲覧画面、読み取り専用のログ一覧、端末調査票、供述調書の体裁で表示する。装飾や行番号は閲覧用であり、証拠には加えない。「原文を開く」は表示せず、メール本文・HTMLソース、ログの全行・全項目、端末資料・供述本文を閲覧領域に直接表示する。ログの構造化表示はJSON変換で値を失わない場合のみ使い、大きい整数や重複キーを含む場合は原文の行表示に戻す。構造化表示でも文字列・数値・null・未記録の区別を保持する。HTML・URL・コマンドは実行しない。

判定結果が出たら、画面上部に「ゲーム作成方法に戻る」を表示する。成功・失敗・提示上限・無罪の各結果で利用でき、結果の会話中も押せる。移動先は既存の`/author`で、画面表示だけでゲームをリセットしない。

## 事件ファイル・会話・判定の表示

生成完了画面の「ゲーム開始」からは、公開ゲームを読み込んで直接「事件ファイル」に入る。中間の開始ページは置かず、通信失敗時のみ理由と再試行ボタンを表示する。事件ファイルは画面高に収める。法廷・場面会話・再検討・判決・審理終了も画面高に合わせ、法廷の長い証言や証拠は文字を省略せずページに分ける。最終判決と事件全体の説明はページ送りをせず同時に表示する。引用・推理を含むすべてのセリフ枠では、話者名を左側に一度だけ表示し、人物画像側には重複表示しない。話者名と本文以外のタイトルを外し、「あなたの視点」などの補足ラベルは表示しない。引用・推理・確認できたことは引き続き会話枠の外に出して帰属を区別する。

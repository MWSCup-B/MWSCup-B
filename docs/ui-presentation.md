# 画面・進捗表示仕様

2026-09-21の利用者要求に基づく画面更新。既存の選択項目、シナリオ承認、技術検証ゲート、ゲームのサーバー判定は維持する。

- `/author` の初期画面は `image/title.png` を使う「インシデントクラフト」。イラストを画面全体に表示し、副題とペンギンの間の空白へ紺・金のゲーム生成ボタンを重ねる。全画面・分割画面で共通の画像内位置に合わせる。ゲーム生成から項目入力へ進む。入力画面とタイトル間では選択を保持する。
- 調査画面では `image/助手.png` から抽出した助手画像と、`image/選択肢.png` を参考にした紺・金・青の証拠カードを表示する。参考画像内の名前・証拠・台詞は教材へ転記しない。証拠は1件ずつ原文で確認し、同じ閲覧領域の下に推理の4択を置く。
- 完成画面のゲーム開始リンクは直接「事件ファイル」へ入る。読み込み中に重複した開始操作を求めず、失敗時は再試行を表示する。
- 事件ファイル、会話、法廷、再検討、判決、審理終了の通常操作は画面内に配置する。長い原文は表示用のページへ分割するが、文字列・改行・空白を保持する。資料選択・ページ切替では採点しない。
- 引用・推理を含むすべての会話で、補足タイトルを表示せず、話者名を会話枠の左側に一度だけ表示する。立ち絵側の重複した名前は表示しない。調査の「原文を開く」は削除し、資料の全行・全項目を直接閲覧できるようにする。
- 引用・推理の会話は独立した参照枠と出典を含む本文を保持する。種別は支援技術向けラベルでも示すが、追加の見出しは出さない。法廷の背景は画面全体で一枚とし、人物領域には重ねない。
- 最終成功時は最後の証拠の説明、検察官が有罪の主張を維持できないと認める会話、弁護士の応答を経て「判決を確認する」から判決へ進む。最終判決と事件の経緯・原因・確認範囲は文章で一つの枠に全文表示する。判決本文のページ送りや最後の争点の解説の重複表示は行わない。判決本文を読む間は争点一覧を省き、文章の領域を確保する。
- 事件ファイルの「事件のあらまし」は削除する。報告書の「疑われた理由」は記録値を引用せず、資料の提出、供述、検察側による被告人への帰属という経緯を説明する。「確認事項」「証言」「検察側の主張と疑いの経緯」を分け、未立証の人物対応を補わない。資料と供述の全文はそれぞれ別の欄で読む。
- 調査対象には、取得元に加えて扱う観測資料の種類を表示する。助手の立ち絵は残し、調査前の用語説明や資料の読み方は表示しない。生成する4択の問題文に攻撃の仕組み・必要な用語・取得済み資料の具体的な値を含め、事件で確認した順序を問う。答えと比較結果は成功後の解説まで公開しない。

## 生成時の進捗

既存APIの `progress` を使う表示専用の計算。利用者の追加要求に従い、完了工程の節目だけを表示する方式から、0〜100の整数を1%ずつ順に表示する方式へ変更した。新規生成は0%から始め、更新先へ40msごとに1ずつ進める。実行中の工程では、その工程の重みに応じた経過時間から推定値を求め、工程完了の値の手前で止める。任意の修正・再試行で工程の重みを重複加算しない。推定値であることを画面に明記し、技術検証ゲートの合否には使用しない。

事件案の確認時は50%で停止し、利用者の承認後に再開する。完了値までの表示を終えてから確認・完成画面へ進む。実行中は最大99%で、サーバーの `READY` 受信後だけ100%を許す。失敗・中止・通信エラー時は推定を止める。新規生成時には表示を0%へリセットする。

| 工程 | 配点 |
| --- | ---: |
| 設定検証 | 5 |
| 接続確認 | 5 |
| シナリオ作成 | 20 |
| シナリオ検査 | 5 |
| 独立検証 | 15 |
| 証拠作成 | 30 |
| 調査構築 | 5 |
| 会話構築 | 5 |
| ゲーム構築 | 5 |
| 最終評価 | 5 |

完了済みの工程と、実行中の工程内の推定を合わせた進行の目安。LLMの内部処理や残り時間の割合を実測した値ではない。承認の要否と技術検証の順序は変更しない。

## インシデント紹介

`public/author.html` に確認済みの短い要約を同梱する。更新時は発生・検知・公表・記事掲載の日付を区別し、未確認の可能性を断定へ変えない。「調査で注目する点」は教材側の読み取り観点。外部本文を実行・AI入力へ転用せず、外部リンクは利用者のクリックで別タブに開く。

生成画面に入るたびに、直前に表示した記事の次の事例を選ぶ。3事例を循環し、同じ記事を連続で初期表示しない。手動切替も記録し、再読み込み後はlocalStorageの直前の記事IDから続ける。保存できない環境でも同じ画面内ではメモリで切り替える。進捗取得だけでは記事を切り替えず、閲覧を中断しない。参照先と記事本文は変更しない。

# 資料調査・画面変更（2026-09-25）

利用者提供の[宿題原文](investigation-homework.txt)は参考情報としてEvidence生成に渡す。最新の利用者要求「宿題の部分は参考程度で、成り立つことを優先」に従い、資料種類・操作回数・コマンド・比較例の再現を必須にしない。選択済みの攻撃経路、OS、取得可能な記録を維持し、その資料で解ける調査を優先する。宿題中のIP・人名・時刻を生成済みの事件へ固定値として追加しない。

## 現在の生成方針（宿題の必須扱いを解除）

Scenario生成・独立レビュー・修正・Evidence生成で、成立性と公開資料による解答可能性を優先する。各資料の調査は1 stepでもよく、必要なときだけ手順を増やす。調査操作の2～4択、提出する反対主張の4択、全資料を最初から選べる方式は維持する。

フィッシングは保存された誘導内容・リンク、実際のWeb要求、後続処理を区別する設計に変更した。表示URLとhrefの不一致やメールとWeb要求の一致を一律には要求しない。HTML形式でなく通常のリンク文字列でもよい。相違・対応を正答に採用するときは、提示する資料にその根拠が必要であり、確認できない関係を補完しない。認証情報フィッシングの送受信記録やStored XSSのスクリプト実行記録など、選択した攻撃の取得定義は維持する。

通常記録は取得条件の範囲で無理なく表現できる場合に加え、件数では生成を停止しない。問題文・解説への観測値の逐語的な繰返しも合格条件から外し、日本語による説明を認める。公開原文の正確な引用・参照・資料の由来、取得定義の必要項目、複数資料による論証、読み取り操作の範囲、秘密情報の非公開は引き続き検証する。宿題由来の表現・件数条件の解除は上記の利用者要求に基づくもので、技術的な検証の失敗を無視する変更ではない。

既存の保存ゲームは変更せず、新規作成・再生成に適用する。以前の検証記録にあるURL不一致・件数・逐語的な値の必須化は旧方針であり、この節で置き換える。

## 調査と提出

新規自動生成は `OPEN_MATERIALS`。全技術資料を開始時から選択できる。本文の自動取得は行わない。資料ごとに `materialInvestigations`（schemaVersion 1.0）を生成し、2～4択の調査を順番に行う。別資料へ自由に切り替えられ、資料別の進行・最後の操作結果をセッションに保持する。

操作結果は封印済みの原文から算出する。表示用コマンドは読み取り専用UTF-8書き出し `material.txt` を対象とし、サーバーでは実行しない。原文の行表示、固定文字列検索、改行数の確認を使用する。出力用の未記録文字列を生成させない。全資料の手順、選択肢数、正解位置、行範囲、原文に存在する観測を検証し、不正な生成は既存の上限付き差し戻しへ進む。

コマンドの意味は [GNU sed](https://www.gnu.org/software/sed/manual/html_node/Overview.html) と [GNU grep](https://www.gnu.org/s/grep/manual/grep.html) に従う。本文中のHTML・SQL・URL・コマンドは文字列として表示する。人物の断定、秘密値の表示、実環境への操作は行わない。

| 宿題の対象 | 資料に応じて採用できる参考例（固定手順ではない） |
| --- | --- |
| フィッシング | メール選択、差出人比較、表示URLとhref、取得済みの要求記録との時刻・URL照合。フォーム送受信記録がある定義では送受信と相関IDも調査 |
| Stored XSS | 保存投稿の対象・日時・原文、閲覧要求、取得可能なブラウザのスクリプト実行記録との照合 |
| ClickFix | 保存された案内と端末のプロセス動作記録を比較し、端末・時刻、対象プロセス、親子関係、起動結果・ユーザーを確認 |
| 不正ログイン | 認証の時間帯・接続元・成否、セッションの受入れ記録を確認。SSHの定義で取得できる場合だけSSH認証・セッションを調査 |
| SQLインジェクション | Web要求とDB監査の相関、SQL全文、入力と条件の比較。認証回避やCSV流出は確定済みの事件にない限り追加しない |
| パスワードスプレー | 時刻、接続元別の試行アカウント、回数・時間分布、取得可能な認証設定を照合。同一パスワード候補使用はログだけで断定しない |
| ランサムウェア | プロセスとファイル検査、取得済みの変更前後の値・要求文を照合。SSH経由でない事件へSSH記録を追加しない |

宿題にあるソースコード、ブラウザ履歴、追加監査、証言等を、取得条件のない事件に存在する資料として捏造しない。独立した資料が必要な場合は、攻撃定義とネットワークの取得条件が先に満たされる必要がある。生成文章の意味と教育的品質は、従来どおり内容レビューも必要。

調査完了後は「保存した証拠を基に反論を考える」から、保存済みの証拠一式を確認し、それらを照合して成立する反論を4択から選ぶ。複数資料を引用する主張は該当資料をすべて調べてから公開する。法廷では保存した証拠一式と選択した反論を表示し、反論の変更には調査へ戻る。失敗時の台詞は法廷背景で表示する。

## 報告書、解説、保存

事件報告書は検察官の理由書として、提出資料、供述、検察側の解釈を分ける。選択攻撃の名前や真の連鎖を冒頭で説明しない。

無罪判決後、事件の解説、資料原文、調査手順・コマンド、争点ごとの解説を表示する。保存済みゲームには初回クリア日時 `clearedAt` を記録し、制作画面の一覧から解説を再閲覧できる。未クリアの解説APIは403。保存失敗時には判決への状態変更を確定せず、同じ操作を再試行できる。

旧保存形式は読み込みを維持する。新しい宿題の調査手順は再生成したゲームに適用される。旧ゲームは記録がないため初期表示は未クリア。プレイ途中のセッションは従来どおりメモリ管理であり、制作画面へ戻る操作は途中セーブではない。

## 画面

全ゲーム画面に制作画面へ戻るリンクを用意。生成ゲームでは右上に常設する。ゲームはビューポート内へ収め、資料一覧・原文・解説等を部分スクロールにする。狭い画面では資料一覧と調査内容を上下に配置する。

制作画面の色をタイトルの紺・金・淡色へ統一。既存のボタン配置と画面構成を維持。人物4役は `image/pengin.png` を参照して生成した独自素材へ変更した。[素材記録](character-assets-2026-09-25.md)。

## モデル・エフォートの選択

シナリオ作成画面でモデルとエフォートを選べる。シナリオ生成、独立検証、修正、証拠生成に同じ指定を使用する。事件の技術的な構成と分離した、生成セッションごとの `generationSettings`（schemaVersion 1.0）として保持する。別セッションやサーバー全体の設定は変更しない。

既定を選ぶと指定用CLI引数を付けず、従来のCodex既定動作を維持する。明示指定には `--model` と `--config model_reasoning_effort="..."` を使用する。shellを通さず個別引数として渡す。利用可能なモデルと推論強度はモデル・クライアント・アカウントに依存し、利用不可の場合は別モデルへ暗黙に変更せずエラーを返す。[OpenAI公式設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference)。

### フィッシングの比較値不足・証拠の再試行上限の修正

前回の修正では合成値の提示が条件付きで残っていた。制作設定の原入力は維持し、「実際に遷移するリンク先」という目標は、生成要件では保存メールの表示URL・hrefと記録されたWeb要求先の比較に限定した。ページ遷移完了を観測したとは扱わない。メールの取得要件に異なる表示URLとhrefを同じ非実行HTMLソースへ必ず含めること、Webの取得要件にtimestampとhrefのパス・クエリに対応するrequest_targetを対象行へ必ず含めることを明記した。

Evidence生成後も、同じ攻撃の保存メールとWeb記録の具体値・対応を検査する。メール単体での比較、メールとWeb要求の照合を、それぞれの資料だけで行える必要がある。文字参照とURLフラグメントは非実行の文字列として扱う。別攻撃の同名資料、欠落した値、別の要求先を比較成立の根拠にしない。

Schema検査後は、ログの形式・必要項目、資料間の対応、調査手順、全4択の原文引用・解説の具体値を独立に検査し、不備を同じFeedbackへ集める。以前は最初のログエラーで検査を打ち切り、最後の試行で解説エラーが初めて現れていた。各Codex呼出しは別の実行なので、再試行に`evidenceRepairBase`として前回のdraftも渡す。試行上限は2回のままで、不備が残れば生成を停止する。
